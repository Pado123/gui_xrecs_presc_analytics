# Paper Artifacts

Self-contained folder with the prompts, train/test data, and experimental results
accompanying the paper on LLM-based Predictive Process Monitoring.

## Structure

```
paper_artifacts/
├── prompts/     — LLM prompt definitions (system prompt + template) per dataset
├── data/        — preprocessed train/test event logs per dataset
└── results/     — Gemini experiment output files per dataset
```

## Contents

### `prompts/`

One JSON file per dataset. Each file contains keys for every experimental mode:

| Key                         | KPI             | Encoding           | Anonymized |
|-----------------------------|-----------------|--------------------|------------|
| `agg`                       | lead_time       | aggregated history | no         |
| `seq`                       | lead_time       | sequential         | no         |
| `agg_outcomepred`           | activity occur. | aggregated history | no         |
| `seq_outcomepred`           | activity occur. | sequential         | no         |
| `agg_hashed`                | lead_time       | aggregated history | yes        |
| `seq_hashed`                | lead_time       | sequential         | yes        |
| `seq_outcomepred_hashed`    | activity occur. | sequential         | yes        |

Each value is an object with:
- `system_prompt`: role and output-format instructions
- `prompt_template`: the user-turn template with `{examples}` and `{test_case}` placeholders

Datasets: `bpi12`, `bac`, `hospital` (and `bpi17`).

### `data/{dataset}/`

- `preprocessed_log_aggr_hist_train_outcome_pred.csv` — training log with
  aggregated-history encoding, target = activity occurrence.
- `preprocessed_log_aggr_hist_test_outcome_pred.csv` — test log (truncated running traces).
- `anonymization_dict.json` — deterministic activity-name → 4-character code mapping
  used in the RQ2 anonymization experiments (`bpi12`, `bac`).

Sequential JSON logs (`preprocessed_log_sequential_{train,test}_{kpi}.json`) are
generated by running `utils/preprocessing_times.py` via `main_pm4py.py`; re-run the
pipeline to regenerate them locally.

### `results/{dataset}/`

Raw Gemini experiment output files.

- `gemini_results_multiple_seeds_n{N}seq_{kpi}[_hashed][_{seed}].json` — one per
  experimental run; each contains per-trace predictions, reasoning text, and
  aggregated metrics (MAE/MAPE/RMAE for lead_time; Precision/Recall/F1 for outcome).
- `gemini_n{N}_op_[hash_].log` — stdout/stderr captured during the run.

The `N` in the filename is the number of in-context examples (2, 10, 100).
Files with `hashed` use anonymized prompts (RQ2). Files with a `_{seed}` suffix
are additional independent runs for the 20-seed aggregation.

## Reproducing the analyses

From the repository root:

```bash
# RQ1/RQ2 summary tables (Tables 1, 2)
python llmp/analysis/aggregate_results.py --output_dir paper_artifacts/results

# RQ2 Nemenyi (Wilcoxon) test
python llmp/analysis/nemenyi_analysis.py --output_dir paper_artifacts/results

# RQ3 beta-learner evaluation (needs sequential JSON data + classification file)
python llmp/analysis/beta_learner_eval.py \
    --dataset bpi12 --kpi lead_time \
    --data_dir experiments/bpi12 \
    --output_dir paper_artifacts/results
```
